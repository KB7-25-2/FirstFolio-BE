# FirstFolio 로컬 관측·부하 테스트 결과

- 실행일: 2026-08-20
- 대상: 로컬 Tomcat의 FirstFolio 백엔드
- 상태: **기준 성능 테스트 통과**

## 1. 테스트 환경

| 구분 | 환경 |
|---|---|
| 애플리케이션 | Java 17, 외부 Tomcat 9.0.118 |
| 데이터베이스 | 로컬 MySQL |
| 부하 발생기 | Docker, `grafana/k6:2.1.0` |
| 메트릭 수집 | `prom/prometheus:v3.13.2` |
| 시각화 | `grafana/grafana:13.1.3` |
| 테스트 데이터 | `load-test/seed-local.sh`로 만든 로컬 전용 최소 시드 |
| 인증 | Firebase ID Token을 사용하는 로컬 테스트 계정 1개 |

Prometheus는 `http://host.docker.internal:8080/internal/metrics`를 정상 수집했고, 타깃 상태 `UP`을 확인했다. k6 결과는 Prometheus remote write로 같은 관측 환경에 저장했다.

## 2. 합격 기준

조회 시나리오에는 다음 기준을 적용했다.

- 검증 성공률: `99% 초과`
- HTTP 실패율: `1% 미만`
- 일반 조회 응답시간: `p95 500ms 미만`
- Firebase 로그인 응답시간: `p95 2,000ms 미만`

온보딩 준비 시나리오는 계정 상태를 변경하는 일회성 흐름이므로 검증 성공률과 HTTP 실패율만 판정했다.

## 4. 테스트 중 발견한 문제와 해결

| 현상 | 원인 | 해결 |
|---|---|---|
| `/internal/metrics`가 `403 INTERNAL_CALL_REQUIRED` 반환 | Tomcat과 호출 측의 `INTERNAL_CALL_TOKEN` 불일치 | Tomcat EnvFile과 Prometheus secret에 같은 토큰을 설정하고 서버를 재시작 |
| `/internal/metrics`가 잠시 404 반환 | 최신 WAR가 아직 배포되지 않은 Tomcat에 요청 | 빌드·재배포가 끝난 뒤 다시 확인하여 200 응답 확인 |
| 온보딩이 `422 LEVEL_TEST_QUESTION_SET_INVALID`로 중단 | 로컬 DB의 대단원·문항·강좌·정책 기준 데이터가 비어 있음 | 로컬 전용 최소 시드 명령 `load-test/seed-local.sh` 추가 및 적용 |
| 온보딩 로그인에서 `401 INVALID_ID_TOKEN` 반환 | `load-test/.env`의 Firebase ID Token이 만료되었거나 더 이상 유효하지 않음 | 테스트 계정으로 다시 로그인해 새 ID Token으로 교체 |
| `learning-read` 기능 검증은 성공했지만 전체 p95 500ms 기준 실패 | Firebase 로그인과 일반 조회 API를 하나의 응답시간 기준으로 합산 | 요청을 `auth`, `read`, `write`로 분류하고 인증 p95 2초·조회 p95 500ms를 별도 판정 |

## 5. 결과 해석과 한계

이번 결과로 다음을 확인했다.

- 로컬에서 Micrometer → Prometheus → Grafana 관측 흐름이 동작한다.
- k6 결과가 Prometheus에 저장되고 Grafana에서 조회된다.
- 신규 사용자 온보딩의 주요 API 흐름이 최소 테스트 데이터로 정상 완료된다.
- 단일 테스트 계정을 공유한 최대 10 VU의 핵심 읽기 흐름에서 HTTP 오류가 발생하지 않았다.
- 현재 로컬 기준 `p95 500ms 미만` 목표를 통과했다.

다음 사항은 이번 결과만으로 판단할 수 없다.

- AWS 운영 사양에서 감당할 수 있는 최대 트래픽
- 서로 다른 사용자 계정을 사용했을 때의 캐시·DB 접근 특성
- 10 VU를 초과하는 부하에서의 한계점
- 상품 매수, 포인트 상점 구매 등 쓰기 API의 동시성 안전성
- 외부 금융 데이터 API가 포함된 수집 작업의 성능
- 장시간 실행 시 메모리 증가나 커넥션 누수 여부

따라서 이번 결과는 **로컬 기준 성능 베이스라인 통과**로 기록하며 운영 수용량 결과로 사용하지 않는다.

## 7. 후속 테스트

- 테스트 계정 풀 50~100개 구성

- 여러 계정 포인트 상점 처리량 테스트
